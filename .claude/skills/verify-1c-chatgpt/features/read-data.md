# Чтение данных

Человек спрашивает обычными словами («5 последних реализаций с контрагентом», «остатки на складах»).
Модель ищет объект (`list_objects`), смотрит поля (`describe_object`), читает (`query`) или считает (`count`).

## Sub-features

- `list_objects`: группы вместо простыни на 1900+ объектов, поиск по нескольким словам.
- `describe_object`: поля, табличные части, ссылки; неточное имя даёт похожие варианты.
- `query`: `select` с путями `Контрагент/Description` подставляет `$expand`; служебные поля OData вычищаются;
  `top` до 1000 (бесплатная версия), дальше `skip`; ответ обрезается около 150 КБ с подсказкой;
  виртуальные таблицы `Balance()`, `Turnovers(...)`, `SliceLast()`; путь за пределы OData отклоняется.
- `count`: число, BOM не мешает.

## Driving it

- smoke `mcp`: шаги `list_objects`, `describe_object`, два `query`, `count`, ошибка неизвестного объекта, `../`.
  Запросы к 1С в `requests.jsonl`: все GET, `$expand=Контрагент` подставлен.
- Граничные случаи (1000 и 5000 строк, обрезка, BOM, кэш `$metadata`): `tests/suite.mjs`, разделы 3 и 5.

## Gotchas

- Предел 1000 строк и тексты про бесплатную версию заданы в `server/index.js` (`MAX_ROWS`, `FREE_LIMITS`)
  и в instructions; тесты проверяют оба места.
